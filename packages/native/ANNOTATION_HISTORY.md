# Sparse annotation history

The editable document keeps two independent structures with one transaction boundary. The Rope owns immutable text roots and cursor metadata. `TextAnnotations` owns one mutable `MarkTree` plus annotation payloads. Text history remains persistent because switching a Rope root is cheap; annotation history is sparse because cloning a mutable tree for every root would make each local edit proportional to the document's annotation count.

Each retained text edit has one move-only `DocumentTransactionJournal` owned by the same Rope undo node as the immutable root and cursor metadata. Its first payload is `AnnotationEditDelta`; later document, move, and style payloads extend the journal rather than adding synchronized stacks. The annotation delta stores the normalized text splice (`start`, old length, new length) and exact before/after values only for annotations that cannot be recovered by the ordinary inverse splice. Policy deletions are always present. Retained marks are present only when applying the forward splice and its inverse would not reproduce the original mark. Insertions and edits far from all marks normally have an empty change list.

Forward edit preparation counts the MarkTree lifecycle report first, then allocates exact affected and covered ID slices. Policy deletion IDs and history changes are also exact-sized; there are no annotation-count-sized report buffers. Before the Rope root is published, preparation has validated position and generation limits, retained internal style ownership for detached values, created the delta, and prepared the Rope undo node. `maxUndoDepth = 0` bypasses both Rope history preparation and delta capture.

Undo and redo move one physical node between Rope lists and replay that node's transaction in the opposite direction. Preparation first builds the positional splice and allocates detached MarkTree nodes for exact-ID recreation or mark-kind changes. It also reserves payload capacity, style ownership, and, for the first undo, the Rope current-state node. Publication then switches the Rope root, commits the prepared MarkTree splice/restoration, updates payload membership, releases replaced live style references, and restores the cursor. No allocation occurs between Rope publication and annotation publication. Redo uses the same path with the delta's after side.

Annotation operations on a live history boundary are journaled into the adjacent sparse delta sides. Operations after an edit update the top undo delta's after side; operations after undo update the top redo delta's before side; when both boundaries exist both are updated. Additions therefore disappear and reappear on the same sides as the former full snapshots, while range/point/payload updates restore the exact opposite value. Explicit ID removal and namespace clear are authoritative: matching values and their retained style references are purged from every undo and redo delta so text traversal cannot resurrect them.

Ownership follows state, not position. A live annotation owns one internal-style reference. Each non-null value stored in a delta owns another reference, allowing policy-deleted annotations to remain detached for arbitrary history depth. Applying a delta acquires any new live references during preparation and releases displaced live references only after infallible publication. Trimming, clearing history, branch replacement, and authoritative purge destroy the Rope node's journal once and release delta-owned references together with delta storage. Retained-Rope compaction explicitly moves journals to cloned physical nodes before releasing old arenas.

The model deliberately adds no copy-on-write annotation state, alternate cache, or second positional index. Rope roots remain persistent, `MarkTree` remains mutable, and sparse deltas contain only the information that ordinary forward/inverse splices cannot reconstruct.
